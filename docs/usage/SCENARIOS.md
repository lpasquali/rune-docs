# Deployment Scenarios

Which RUNE deployment do you need? Match your scenario to a row, then follow the linked install + configuration pages.

## Decision matrix

| Scenario | Install path | Config highlights | Operational notes |
|---|---|---|---|
| [Air-gapped](#air-gapped) | rune-airgapped bundle + on-prem k8s | Bundle SHA256SUMS verification; offline cosign verify; `RUNE_DB_URL` to on-prem PostgreSQL | Tracks `rune-airgapped` repo for bundle cadence |
| [Edge (k3s)](#edge-k3s) | Single-node k3s + Helm | `RUNE_BACKEND=local`; TDP energy cost model | Observability subset; no S3 (local disk) |
| [Multi-tenant](#multi-tenant) | Per-cloud install + namespace-per-tenant | `rune.api.tokens` per team; namespace RBAC | Rate limits + cost attribution per tenant |
| [Regulated on-prem](#regulated-on-prem) | On-prem k8s + rune-audit + compliance | SLSA L3 evidence collection; ML4 audit trail | Auditor-ready evidence bundle per release |
| [Local dev](#local-dev) | pip-CLI or docker-compose | `RUNE_BACKEND=local`; no auth | Hot-reload; dev env only |
| [CI-inline](#ci-inline) | docker-compose + headless runner | `scripts/e2e.sh` (per rune-docs#271 Phase 1) | Ephemeral state; artifact upload |

## Air-gapped

**Who**: defence, regulated manufacturing, TS/SCI environments — any deployment where outbound internet access is blocked by policy.

**Install**: the `rune-airgapped` repo ships an OCI bundle with all images + SBOMs + cosign signatures. Landing path: on-prem Kubernetes via [operations/DEPLOYMENT.md §Mode 4](../operations/DEPLOYMENT.md#mode-4-kubernetes-production), with per-cloud equivalents landing under [#277](https://github.com/lpasquali/rune-docs/issues/277).

**Config**:

- Verify the bundle: `sha256sum --check SHA256SUMS` then offline cosign-verify against the shipped public keys.
- Point `RUNE_DB_URL` at your internal PostgreSQL (SQLite is the current default but doesn't scale across pods; [DATABASE_HA.md](../operations/DATABASE_HA.md) covers PostgreSQL CNPG planning).
- S3-compatible backend for results sink: your internal MinIO/Ceph RGW; set via Helm values.

**Operational**: zero outbound calls at runtime. Bundle rebuilds are the sole supply-chain touchpoint; stage those via your internal mirror.

## Edge (k3s)

**Who**: single-node regional deployments, field devices, small-footprint on-prem where a full k8s control plane is overkill.

**Install**: k3s single-node + `rune-charts` with values tuned for low-resource footprint (no rune-operator, single API replica, local-path provisioner).

**Config**:

- `export RUNE_BACKEND=local` — skips cost gates and uses TDP energy model (see [SYSTEM_PROMPT §Cost gates](../context/SYSTEM_PROMPT.md#cost-gates-api-contracts)).
- Observability subset: Prometheus scrape on the API pod; skip Loki/Tempo unless you have upstream storage.
- No S3 — results land on a local PVC.

## Multi-tenant

**Who**: platform-engineering teams hosting RUNE for multiple internal teams or external customers.

**Install**: any cloud-specific path from [#277](https://github.com/lpasquali/rune-docs/issues/277) with namespace-per-tenant layering on top.

**Config**:

- `rune.api.tokens` set per team (one token per tenant) — tokens are compared with `hmac.compare_digest` at the API boundary per [rune#217](https://github.com/lpasquali/rune/pull/217).
- NetworkPolicies between tenant namespaces.
- Per-tenant PostgreSQL schema (multi-schema on one PostgreSQL, or one DB per tenant — ADR 0006 covers trade-offs).
- Cost attribution: `CostEstimation*` events tagged with tenant token id; pipe into your existing FinOps tooling.

**Operational**: rate-limit the API behind a tenant-aware ingress (nginx `limit_req_zone` keyed on auth token, or similar). Benchmark jobs queued per tenant if GPU budget is shared.

## Regulated on-prem

**Who**: industries under ISO 27001 / IEC 62443 / SOC 2 scrutiny where deployment evidence feeds audits.

**Install**: on-prem path from [#277](https://github.com/lpasquali/rune-docs/issues/277) + `rune-audit` CronJob (see [rune-charts #57 / rune-audit #23 story in CURRENT_STATE](../context/CURRENT_STATE.md)).

**Config**:

- Enable full SLSA L3 provenance validation on image pulls (admission controller enforcing cosign signatures).
- `rune-audit` CronJob collects ML4 evidence weekly (IEC 62443-4-1 SDL/SM/SVV/DM/SUM; see [security/SDL.md](../security/SDL.md) and the forthcoming [compliance matrix](https://github.com/lpasquali/rune-docs/issues/282) under #273).
- TLS for every inter-service edge; mTLS via service mesh if policy requires.
- Air-gapped update channel: combine with the air-gapped scenario above.

**Operational**: per-release auditor-ready evidence bundle generated by `rune-audit` + archived to WORM storage.

## Local dev

**Who**: developers writing new drivers, benchmarks, or charts.

**Install**: [QUICKSTART Path 1 or Path 2](QUICKSTART.md#path-1-pip-cli) — pip-CLI against an existing Ollama, or docker-compose for the full stack.

**Config**:

- `RUNE_BACKEND=local` — no cost gates.
- `RUNE_API_AUTH_DISABLED=1` — no token required (never in production).
- Volume-mount the source tree into the compose stack for hot reload: `volumes: - ./rune_bench:/app/rune_bench` in `docker-compose.override.yml`.

## CI-inline

**Who**: CI pipelines validating a commit's behavioural impact on benchmark scores.

**Install**: runs inside the existing CI runner (GitHub Actions, GitLab, Jenkins). Uses the docker-compose path ephemerally via `scripts/e2e.sh --mode compose` — the one-command wrapper shipping under [rune-docs#271 Phase 1](https://github.com/lpasquali/rune-docs/issues/271) with the binding spec already in [E2E Testing](E2E_TESTING.md) (landing under PR [#272](https://github.com/lpasquali/rune-docs/pull/272)).

**Config**:

- Ephemeral stack: teardown-on-exit; no persistent volumes.
- Artifact capture: `e2e-artifacts/` directory per the spec; uploaded as workflow artifacts.
- Evidence marker `<!-- e2e-artifacts/summary.md -->` pasted into the PR body; `rune-ci/.github/workflows/pr-compliance.yml` Phase 2 validator verifies it.

**Operational**: cold builds ≈ 5–10 min; warm loop ≈ 60–90 s. Matches `--timeout 600` default.
