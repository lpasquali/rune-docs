# Contributing to rune-docs

First off, thank you for considering contributing to rune-docs! It's people like you that make the Rune documentation such a great resource.

## Where do I go from here?

If you've noticed an issue in the documentation, found something unclear, or have an idea for new content, please open an issue or discussion first. It's generally best to get confirmation or feedback on your proposal before you start working on changes.

## Fork & create a branch

If this is something you think you can help with, then fork the `rune-docs` repository and create a branch with a descriptive name.

## Set up your docs environment

Make sure you have the tools needed to build and preview the documentation installed (for example, any static site generator or documentation framework used in this project).
Follow the README or project-specific documentation to build and preview the site locally so you can verify how your changes will look.

## Implement your changes

At this point, you're ready to make your documentation edits (fixing typos, clarifying explanations, adding examples, or writing new guides). Feel free to ask for help; everyone is a beginner at first.

## Improve examples and guides

If you're adding new examples, tutorials, or reference material, ensure they are accurate, up to date with the current Rune behavior, and clearly documented so readers can follow along.

## Make a Pull Request

At this point, you should switch back to your main branch and make sure it's up to date with rune-docs's main branch. Tests should pass on your branch.

## Code of Conduct

Please note that this project is released with a Contributor Code of Conduct. By participating in this project you agree to abide by its terms. See `CODE_OF_CONDUCT.md` for more information.
